# 上线检查清单

从零到能给别人用，按顺序走一遍。微信的规则会变，**所有结论以微信公众平台当下的提示为准**，这里只告诉你「有哪些坑要处理」。

---

## 阶段 0：先跑起来（不用注册任何东西，1 小时）

- [ ] 装 [微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
- [ ] 启动后端：`cd server && node index.js`（需要 Node 18+）
- [ ] 开发者工具 → 导入项目 → 选 `miniprogram` 目录 → AppID 选「测试号」
- [ ] 详情 → 本地设置 → 勾选 **不校验合法域名**（线上必须配好域名后取消勾选）
- [ ] 随便粘一个链接点「一键去水印」，能看到内置演示视频 = 整条链路通了
- [ ] 打开 `http://127.0.0.1:8000/admin?token=admin123`，能看到刚刚产生的 UV / 计算次数 / 广告点击

---

## 阶段 1：账号与资质

- [ ] 注册小程序：<https://mp.weixin.qq.com>（个人主体可以注册，但**可选类目少、不能做需要资质的业务**）
- [ ] 选类目：去水印工具一般挂在 **工具 → 效率** 或 **工具 → 信息查询** 下，个人主体可选范围要以后台实际列表为准
- [ ] 想清楚变现路径：广告变现需要先有量（见阶段 4），个人主体也能开通流量主

> ⚠️ **法务红线**：这类工具处在一个比较敏感的位置。不要出现「破解」「免费下载别人的作品」这类表述；
> 页面上要有「结果仅供个人合法用途、请尊重原作者版权」的说明；不要用其他平台的官方 logo 做图标（商标风险）。
> 本项目内置的图片资源全部是代码画的，可以直接用。

## 阶段 2：服务器与域名

- [ ] 买一台服务器（1 核 2G 起步就够）+ 一个域名，**域名要完成 ICP 备案**（用大陆服务器必须备案）
- [ ] 配置 HTTPS 证书（用 Nginx 反代到 `127.0.0.1:8000`；`certbot` 可以免费签）
- [ ] 把服务跑起来（不要裸 `node index.js`，用进程守护）：
  ```bash
  # 方式一：pm2（最省事）
  npm i -g pm2
  cd /path/to/server && pm2 start index.js --name qushuiyin && pm2 save
  # 方式二：systemd（更干净），参考下面的 unit 文件
  ```
- [ ] **`.env` 里这三项必须改掉**（不改等于把数据和钱袋子敞开）：
  - `TOKEN_SECRET` → 一串随机长字符串
  - `ADMIN_TOKEN` → 看板口令
  - `WX_APPID` / `WX_SECRET` → 小程序后台「开发管理 → 开发设置」里拿
- [ ] `.env` 不要提交到 Git（已经在 `.gitignore` 里）
- [ ] 服务器只对外暴露 443，8000 端口不要直接开到公网

<details>
<summary>systemd unit 示例</summary>

```ini
[Unit]
Description=qushuiyin server
After=network.target

[Service]
WorkingDirectory=/path/to/server
ExecStart=/usr/bin/node index.js
Restart=always
RestartSec=3
Environment=NODE_ENV=production

[Install]
WantedBy=multi-user.target
```
</details>

## 阶段 2B：走微信云托管（免域名、免备案，新手推荐）

> 适合不想买域名、等不起备案的情况。云托管有免费额度；小程序通过**内网专线**调用后端，
> 不用在小程序后台配「request 合法域名」，后端也不暴露在公网上。

- [ ] 微信云托管控制台 → 新建环境（选你的小程序）→ 服务列表里新建服务，服务名记下来（填到小程序配置里，默认写 `server`）
- [ ] 项目根目录执行打包：`powershell -ExecutionPolicy Bypass -File tools\打包云托管.ps1`
      （产物在 `dist\云托管部署包`，每次改完代码重新执行一次即可；脚本会换新密钥并自检配置）
- [ ] 控制台 → 你的服务 → 部署发布 → 「选择方式」选**手动上传代码包** → 上传方式选**文件夹** →
      选中 `dist\云托管部署包` → 点「发布」，等 2~3 分钟
- [ ] 小程序端填云托管信息：`miniprogram/config/index.js` 里的 `CLOUD.envId`（环境 ID）和 `CLOUD.service`（服务名）
- [ ] 小程序后台「设置 → 功能设置 → 基础库最低版本设置」改成 `2.23.0` 或更高（`callContainer` 的硬性要求）
- [ ] **素材域名白名单必须配**：`docs/微信合法域名-200个.txt` 贴进 downloadFile 合法域名。
      云托管没有可用的公网下载域名，素材全部走 CDN 直连，白名单里没有的平台会保存失败
- [ ] 想看数据看板：服务设置里打开「公网访问」，用 `dist\云托管部署包\部署说明.txt` 里的口令访问
      `公网域名/admin?token=口令`（官方说默认公网域名仅供测试，看板这点用量没问题）

> ⚠️ **云托管容器没有持久硬盘**：`data` 目录（UV / 计算次数 / 广告点击 / 用户余额）在**重新发布后会清空**。
> 所以别频繁重发；要长期保存得接云托管 MySQL 或对象存储，改造点是 `server/src/store.js`（唯一的数据出入口）。

## 阶段 3：小程序端配置

- [ ] `miniprogram/project.config.json` → `appid` 换成自己的
- [ ] `miniprogram/config/index.js`：
  - `ENV` 改成 `'prod'`
  - `prod.apiBase` / `prod.mediaProxy` 改成 `https://你的域名`
- [ ] 公众平台「开发管理 → 开发设置 → 服务器域名」配置：
  - **request 合法域名**：`https://你的域名`
  - **downloadFile 合法域名**：`https://你的域名`（保存到相册、视频预览都要用）
  - **downloadFile 再补一批第三方 CDN 域名**：打开 `docs/微信合法域名-200个.txt`，
    把里面 200 行整段粘进去。这是服务商给的合法域名清单（原始 431 个，微信每类上限 200 个，
    已按平台使用频率挑好）。加了之后用户下载视频**不经过你的服务器**，省带宽、也更快；
    没加的域名会自动回退到中转，用户无感，只是流量算你的
  - 域名必须 HTTPS，且不能带路径
- [ ] 隐私协议：「设置 → 服务内容声明 → 用户隐私保护指引」里声明会使用**相册（仅写入）权限**，
  否则调用保存到相册会被拦截。代码侧 `app.json` 已经配了 `__usePrivacyCheck__: true`，
  并内置了隐私授权弹窗组件（`components/privacy-popup`）
- [ ] 小程序名称 / 简介 / 头像：别出现「破解」「去水印神器」这类词，容易被驳回

## 阶段 4：流量主与广告位

- [ ] 开通流量主：公众平台「流量主」入口，**一般要求小程序累计独立访客 ≥ 1000**（以后台显示的门槛为准）
- [ ] 创建广告位，把拿到的 `adunit-xxxx` 填进 `miniprogram/config/index.js` 的 `adUnits`：
  - `bannerHome` → 首页底部 banner
  - `bannerResult` → 结果页底部 banner
  - `rewardedVideo` → 激励视频（**用户点「保存到相册」时弹的就是它**，最重要，优先配好）
  - `interstitial` → 插屏（结果页返回首页时展示）
- [ ] 广告位 ID 没配好之前，把 `adEnabled` 设为 `false`，否则开发者工具里会一直报错

> 💡 **广告和次数的关系**：解析免费；「保存到相册」消耗 1 次；次数只能看广告获得，
> 看一次 +10 次、24 小时内有效。参数在 `server/.env`：`REWARD_PER_AD` / `REWARD_VALID_HOURS` / `MAX_REWARD_PER_DAY`。
> **这些值服务端说了算**（改客户端没用），`miniprogram/config/index.js` 里那份只是没连上服务器时的展示兜底。
>
> ⚠️ 没有拿到真实的 `adunit-xxx` 之前（占位值 `adunit-0000...`），激励视频会「放不出来」，
> 而项目**不会因此拦住用户**，而是放行保存并打一条 `ad_fail_open` 埋点。
> 这样开发和审核阶段都不会卡死用户；上线后如果 `ad_fail_open` 很多，先查广告位配置。

## 阶段 5：解析接口（决定这个工具能不能用）

**已定方案：只用买来的第三方接口**（大圣API `api.zhuceka.cn`，2026-09 实测通过），配置都在 `server/.env`：

  ```ini
  PARSE_PROVIDER=http                # 解析全部走第三方
  PARSE_FALLBACK_PROVIDER=           # 没配兜底（自建代码留着，想切回去再填 selfhosted）
  PARSE_API_URL=https://api.zhuceka.cn/home/api?type=dsp&uid=你的UID&key=你的KEY&url={url}
  PARSE_API_METHOD=GET
  PARSE_API_HEADERS=                 # 密钥在 URL 里，这里留空
  PARSE_FIELD_VIDEO=data.video       # 从返回 JSON 里取视频直链的路径，填错是最常见的失败原因
  PARSE_FIELD_COVER=data.cover
  PARSE_FIELD_TITLE=data.title
  PARSE_FIELD_IMAGES=data.images     # 图集：没视频直链时用第 1 张兜底
  ```

- [ ] 去服务商后台确认**套餐额度、超量计费、有没有限速**，记下额度用完的日期
- [ ] **超时按服务商公告设置**：短视频解析 60 秒（`server/.env` 的 `PARSE_TIMEOUT=60000`，已配好）。
      公告里还提到「文案提取 300 秒」，本项目没有文案提取功能，不用管
- [ ] **保持余额充足**：点数用完时解析会失败，用户看到的是「解析服务正在维护，请稍后再试」，
      看板「计算次数」卡片会红字提示「⚠ 服务商点数不足 N 次，去充值」；充完值不用改代码，下一条解析就恢复
- [ ] 换服务商时：拿对方的「成功返回 JSON 示例」，把上面 `PARSE_FIELD_*` 的路径照着数一遍就行
- [ ] 验证第三方：`cd server && node tools/test-parse.js "抖音链接" --provider=http --download`
- [ ] 验证整体：`cd server && node tools/smoke-test.js`，确认三个核心指标和解析都正常

> **密钥安全（重要）**：这类接口的密钥通常直接写在请求地址里。
> `server/.env` 绝对不能提交到 git（`.gitignore` 已经挡掉了），也别把带 key 的完整地址发到群里或截图外传 ——
> 泄露了等于别人拿你的钱在刷接口。真泄露了就去服务商后台重置密钥。
> 好消息：小程序端只请求你自己的服务器，第三方域名**不用**加进微信后台的「request 合法域名」。

> **自建解析的真实成本**：不花钱，但要人维护。原理是抓平台公开分享页里的 `_ROUTER_DATA`，
> 再把带水印地址换成原片地址，没有用任何逆向签名，所以风险可控。
> 代价是平台一改版就会失效 —— 上线后要盯看板的「解析成功率」和「自建降级次数」，
> 掉下去就说明该修适配器了。强烈建议至少配上第三方兜底，改版时用户不会卡住。
> 另外：平台用户协议原则上不鼓励这种抓取，别把接口再包一层对外卖。

## 阶段 6：提交审核与上线

- [ ] 先传**体验版**，自己拿真机（iOS + Android 各一台）把这三条走通：
      解析 → 保存到相册 → 看广告加次数
- [ ] 检查埋点：真机操作后在 `http://你的域名/admin` 上能看到对应的事件和数字
- [ ] 提审时在「功能页面」里把去水印的完整流程录屏说明清楚，减少被驳回的概率
- [ ] 上线后建议开启灰度，观察 `parse_fail` 事件量（`/admin` 的「事件明细」里看），
      一旦某平台改版，失败率会立刻涨起来

## 阶段 7：上线后要盯的数

| 看什么 | 在哪看 | 异常信号 |
| --- | --- | --- |
| UV / 新增 | 看板首行 | 突然掉一半 → 可能被限流或搜索降权 |
| 解析成功率 | 看板「解析成功率」 | 低于 70% → 解析接口出问题了，赶紧切备用 |
| 广告点击 / 完播 | 看板「广告点击」「激励视频完播」 | 点击高但完播低 → 广告太打扰，用户跳过 |
| 保存转化 | 看板「保存到相册」 | 保存/点击保存 < 50% → 相册权限或下载失败，看 `download_fail` 的 reason |
| 流量主收益 | 微信公众平台「流量主 → 数据」 | 这是权威口径，和自建埋点对不上时以它为准 |

## 常见驳回/线上问题速查

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 解析一直失败 | 链接过期 / 平台改版 / 接口欠费 | 换链接试；看 `data/events/*.jsonl` 里 `parse_fail` 的 msg |
| 保存到相册没反应 | 没声明隐私协议 / 用户拒过权限 | 补隐私协议；代码里已做「去设置」引导 |
| 视频能播不能存 | `downloadFile` 域名没配 | 补 downloadFile 合法域名 |
| 看广告提示不可用 | 广告位 ID 是占位的 / 流量主没开通 | 填真实 adunit-id，或把 `adEnabled` 设为 false |
| 看板打不开 | 口令不对 / 端口没放行 | 口令是 `.env` 里的 `ADMIN_TOKEN` |
| 一个链接解析出别人的水印 | 部分作者把水印做进了画面 | 无解，属于内容本身 |
